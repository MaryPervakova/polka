# Полка — чек-лист приёмки MVP

Обновлено: 25 ноября 2026 года. Статус: подготовлен по подтверждённым правилам. Обнаружен стартовый Vite-шаблон, но бизнес-функции «Полки» не реализованы и ни один пункт не выполнен. Это проверки будущей реализации, а не отчёт об успешных тестах. Основание: 51 пункт исходных сценариев, решения текущего чата, словарь и импорт.

Флажок отмечается после проверки с указанием среды/версии и результата. Поведение по открытым Q не считать принятым до решения. Технические способы тестирования выбрать после стека.

## Доступ — MVP-13, BR-01

- [ ] T-01. Лид и сотрудник Тильды создают, просматривают и редактируют карточки обоих типов независимо от участия в проекте.
- [ ] T-02. Они могут удалять, восстанавливать и безвозвратно удалять любые карточки по установленным подтверждениям.
- [ ] T-03. Другие направления просматривают каталог, ищут и открывают материалы, но не создают и не изменяют карточки, не удаляют и не восстанавливают их, не меняют справочники. Корзина им скрыта и недоступна, включая прямые запросы; лид и сотрудники Тильды её просматривают.
- [ ] T-04. Только лид создаёт, переименовывает и удаляет тематики; только лид добавляет и удаляет теги. Переименование тегов отсутствует.
- [ ] T-05. До SSO сервис доступен только инициатору; временный командный вход не открыт. Нет самостоятельной регистрации, локальных приглашений или подмены корпоративного входа Google OAuth.
- [ ] T-06. При командном запуске проверено соответствие корпоративной личности и ролей матрице BR-01; детали зависят от Q-10.
- [ ] T-07. Исторические имена и связи с карточками сохраняются после ухода сотрудника; «Полка» не вводит специальное автоматическое отключение по этому событию.

## Карточки и создание — MVP-01, 03, 04; BR-02, 03

- [ ] T-08. Карточка соответствует странице проекта; варианты используются для двух страниц одного проекта, например RU / EN, а не разных проектов. Необязательный тип «Проект» / «Продукт» имеет одинаковый состав полей.
- [ ] T-09. Общей карточки продукта, вложенности и наследования материалов нет.
- [ ] T-10. Обязательных полей нет при создании и редактировании новых/старых карточек обоих типов. Сохраняется любая часть сведений без названия, типа, статуса, людей и ссылок; данные можно дополнить позже. Фиктивные значения не подставляются.
- [ ] T-11. Ссылка на общий проект или папку Tilda не заменяет конкретную страницу; опубликованный URL вместо конструктора не принимается как конструктор.
- [ ] T-12. Можно сохранить страницу в работе без опубликованного адреса и без ссылки конструктора, в том числе до появления страницы Tilda.
- [ ] T-13. Можно создать опубликованную и снятую с публикации страницу; статус задаётся вручную.
- [ ] T-14. Новая карточка вне Tilda сохраняется с сайтом, репозиторием, обоими или без обоих; ссылки можно дополнить позже.
- [ ] T-15. Любое ранее заполненное поле можно очистить; пропуски не блокируют сохранение. Форматы и ограничения заполненных значений проверяются независимо от полноты.
- [ ] T-16. Одинаковые названия, опубликованные URL, ссылки ТЗ и Figma в разных карточках не блокируются.
- [ ] T-17. Заказчик вводится свободным текстом и не объединяется с ответственным. Можно назначить нескольких исполнителей.
- [ ] T-18. У карточки собственные данные и материалы; варианты используют общий статус, исполнителей и превью без отдельных значений.
- [ ] T-19. Варианты двух страниц одного проекта хранят подписи и соответствующие ссылки Tilda/опубликованные URL в одной карточке; пропуски не блокируют сохранение. Адреса не связываются по позиции без проверки.
- [ ] T-20. ТЗ и Figma сохраняются списками без подписей, ссылки открываются. Лог ТЗ остаётся отдельным описанием задачи.

## Дубли — MVP-08, BR-04

- [ ] T-21. При совпадении конкретной страницы Tilda с каталогом новая карточка не создаётся; показана существующая с предложением открыть её.
- [ ] T-22. Проверена каждая ссылка Tilda среди вариантов, включая карточки в корзине; при совпадении в корзине предлагается восстановить запись, а не создать новую.
- [ ] T-23. Обнаружение дубля не восстанавливает карточку автоматически и не обходит права.
- [ ] T-24. Заполненные ссылки сравниваются по pageid при создании и изменении; дополнительные параметры не создают новую идентичность. Исходная ссылка сохранена, собственная карточка не считается дублем себя, пустые ссылки не сравниваются. Нераспознанная ссылка получает пояснение без автоматического исправления. Опубликованные адреса и материалы не становятся основанием запрета дубля.

## Статусы — MVP-06, BR-05

- [ ] T-25. Доступны ровно шесть согласованных статусов; возможен любой ручной переход в любой другой.
- [ ] T-26. Для правок «На поддержке» сотрудник вручную ставит «Черновик», затем вручную возвращает «На поддержке»; автоматических переходов нет.
- [ ] T-27. При архивировании ссылки и материалы, включая прежний опубликованный URL, сохраняются.
- [ ] T-28. Смена статуса не публикует и не снимает страницу во внешней Tilda; «Черновик» не требует отсутствия опубликованной версии. Система не меняет статус по ссылкам, теме или другим признакам и не назначает приоритет при их пересечении.
- [ ] T-29. Статус, тематический таб и корзина независимы; архивный таб не назначает статус «Архив в паблике» автоматически.

## Каталог, поиск и тематики — MVP-01, 02, 10; BR-06, 07, 10

- [ ] T-30. На карточке каталога только превью, название и статус; тип, исполнители и остальные сведения внутри подробной карточки.
- [ ] T-31. Поиск по части названия без учёта регистра, полному опубликованному URL или его части без `https://` находит карточку; URL любого варианта участвует в поиске. Показаны все совпадения, при их отсутствии — «Ничего не найдено» с возможностью сбросить фильтры.
- [ ] T-32. Поиск охватывает все темы независимо от открытого таба и оба архивных статуса, исключает корзину.
- [ ] T-33. В каждом фильтре статуса, типа и исполнителя можно выбрать несколько значений. Внутри фильтра — «ИЛИ», между фильтрами и поиском — «И»; пустой фильтр не ограничивает выдачу. Например, два статуса и два исполнителя находят любой из выбранных статусов с хотя бы одним выбранным исполнителем. Несколько выбранных типов в фильтре не назначают несколько типов самой карточке. Фильтра заказчика и поиска по Tilda нет.
- [ ] T-34. Тематика выбирается вручную: одна либо отсутствует; без темы карточка доступна в «Без темы».
- [ ] T-35. При удалении тематики её карточки переходят в «Без темы», ссылки и материалы сохраняются.
- [ ] T-36. Создание и сохранение правок обновляют системное время, сортировка идёт от новых к старым; ручная дата изменений страницы и её отсутствие не определяют порядок.
- [ ] T-37. Просмотр и переход по ссылкам порядок не меняют.
- [ ] T-38. До редактирования сохраняется фактический порядок листов и строк реестра. После сохранения правок карточка участвует в обычной сортировке, взаимный исходный порядок остальных сохраняется. Восстановление возвращает прежнее место; изменения справочников тематик и тегов не поднимают связанные карточки.
- [ ] T-39. Основные сценарии работают на согласованных компьютерах и ноутбуках; мобильная версия не включается в критерий MVP.

## Превью — MVP-09, BR-07

- [ ] T-40. Превью вручную загружается и заменяется; PNG, JPG/JPEG, WebP до 5 МБ допускаются, неподходящий формат и превышение ограничений отклоняются.
- [ ] T-41. Без превью карточка показывает нейтральную заглушку и название; автоматического получения и обновления нет.

## Редактирование и даты — MVP-05, BR-03, 08

- [ ] T-42. Правки применяются только через «Сохранить»; «Отмена» отбрасывает текущие изменения; автосохранения нет.
- [ ] T-43. При уходе с несохранёнными правками из создания или редактирования есть «Продолжить редактирование» и «Выйти без сохранения», действия соответствуют названиям.
- [ ] T-44. Сохранение устаревшей версии отклоняется с предупреждением, введённые данные остаются в форме. «Открыть актуальную версию» открывает её отдельно для сравнения и ручного переноса правок. Молчаливой или принудительной перезаписи и автоматического объединения нет.
- [ ] T-45. Можно сохранить пустой блок изменений, только дату, только описание или оба поля и позднее дополнить. Будущая заполненная точная дата запрещена; календарное «сегодня» определяется по Москве (`Europe/Moscow`), независимо от часового пояса устройства/сервера. Точные даты показаны как ДД.ММ.ГГГГ.
- [ ] T-46. Хранится одна последняя запись без автора и истории; дата не подменяется системным временем и лог ТЗ не подменяет описание.
- [ ] T-47. Неизвестная дата начала остаётся пустой; запрет будущей даты изменений не переносится автоматически на дату начала. Дата окончания не добавляется.

## Теги — MVP-11, BR-11

- [ ] T-48. Можно выбрать несколько доступных тегов; исходные семь имён сохранены буквально, включая «Стандартный блоки», и добавлены четыре утверждённых: Three.js, `<model-viewer>`, lidrekon, GoogleSheet. Всего 11 начальных тегов.
- [ ] T-49. Пока тег удалён, он остаётся в ранее связанных карточках, включая обычное редактирование, но недоступен для нового назначения. При повторном добавлении имени лидом возвращается тот же тег: прежние назначения сохранены, он снова доступен для выбора, второй одинаковый тег не создан.
- [ ] T-50. Четыре утверждённых дополнительных тега сохранены в справочнике и исходных назначениях карточек без замены похожими; другие неизвестные значения требуют отдельного решения и сохраняются в снимке.

## Корзина — MVP-07, BR-09

- [ ] T-51. Перед перемещением в корзину показано «Отмена» / «Удалить», без требования ввести название; отмена сохраняет карточку на месте.
- [ ] T-52. Запись хранится в корзине бессрочно без автоматической очистки, доступно восстановление по правам.
- [ ] T-53. Перед окончательным удалением есть отдельное «Удалить безвозвратно?» с предупреждением о невозможности восстановления и действиями отмены/подтверждения; без подтверждения удаления нет.
- [ ] T-54. Карточки удаляются и восстанавливаются независимо; внешние Tilda, Figma и документы остаются без изменений.

## Первоначальный импорт — MVP-12, BR-12

- [ ] T-55. Старые карточки перенесены автоматически; инициатор выполнил первичную проверку, ручной ввод всего реестра не потребовался.
- [ ] T-56. Неполные старые записи, включая пустые тип, статус, людей и частичный блок изменений, сохранены без вымышленных значений, отметки «Не хватает данных» и смены статуса по неполноте. Частичное дополнение сохраняется по общему правилу отсутствия обязательных полей.
- [ ] T-57. Начальные тематики соответствуют названиям предметных листов, включая «Не на Tilda» и переименование архивного таба в «Архивные в паблике». Индекс «Реестр» и «Шаблон» не создали тематик или карточек; пустые и служебные строки не создали карточки, исключения отражены в сверке.
- [ ] T-58. Две страницы вне Tilda включены, исходные GitHub сохранены. Если «расположение на сервере» — опубликованный URL, оно перенесено в ссылки сайта; внутренний путь/пояснение сохранено только в снимке, новое поле не добавлено. Подмены ссылкой Tilda нет.
- [ ] T-59. Архивный таб «Архивные в паблике» сохранён отдельно; статусы не преобразованы. Количества сверены с восстановленным снимком, а не только с текстом старого отчёта.
- [ ] T-60. Строки вариантов не разделены автоматически; соответствие опубликованных адресов и ссылок конструктора проверено, не угадано по позиции. Старые строки с большим числом ссылок проверены на условие двух страниц одного проекта; спорные случаи учтены в отчёте Q-12 без потери исходных данных.
- [ ] T-61. Семь исходных строк без конкретной страницы Tilda сохранены с отсутствующей ссылкой; недостающие pageid не вымышлены. Отсутствие ссылки допускается общим правилом свободного заполнения.
- [ ] T-62. Старые неточные даты отображаются исходным текстом, точная дата остаётся пустой; дата импорта и вымышленный день не подставлены.
- [ ] T-63. Прежние имена и ответственные сохранены, не привязаны к корпоративным аккаунтам по одному имени и не заменены текущим лидом автоматически.
- [ ] T-64. Дубли источника показаны отдельным списком; пользователь определил итог без автоматического объединения и потери материалов.
- [ ] T-65. Извлечены фактические гиперссылки и ссылки фрагментов; поясняющий текст сохранён в снимке, статусы не выведены автоматически из текста ячеек.
- [ ] T-66. Дополнительные поля бэклога сохранены в исходном снимке, но не появились в интерфейсе MVP; отсутствующее описание изменений не заполнено логом ТЗ.
- [ ] T-67. До импорта восстановлены снимок и отчёт, разобраны спорные строки без автоматического разделения и потери ссылок. Итоговые карточки, варианты, исключённые строки и порядок сверены с источником; происхождение записей прослеживается. Число исходных строк не выдано за число карточек без проверки.
- [ ] T-68. Нет постоянной синхронизации, пользовательского экрана повторного импорта, автоматически созданных задач планирования или истории действий из реестра.

## Дополнительные рекомендации по технической проверке

Это предложения методов, не новые пользовательские функции и не выполненные проверки:

- Проверить React/TypeScript/Vite, расширение `.tsx` у React-компонентов и sx через поддерживающие компоненты/адаптер без утечки в DOM; общие стили — обычный CSS.
- Проверить чтение и запись рабочей XLSX-книги после перезапуска: Excel — основное хранилище, не экспорт. Проверить связи листов, кириллицу, пустые поля, даты и длинные тексты без молчаливой обрезки.
- Проверить последовательную очередь сохранений, две вкладки, версии карточек и уникальность pageid; занятый или изменённый извне файл не должен затираться молча.
- Имитировать отказ записи/замены, нехватку места и сбой между подготовкой файла и фиксацией. Последняя корректная книга и связанные превью должны восстанавливаться; успех не показывается до сохранения.
- Проверять серверные операции под каждой ролью, включая запросы без доступных в UI кнопок.
- Проверить две одновременные попытки создать одинаковую Tilda-ссылку и два сохранения одной карточки.
- Для служебного импорта проверить повторный прогон на копии данных и сверку происхождения; повторяемость пока предложение архитектуры.
- Перед командным запуском проверить восстановление XLSX и превью, пригодность последовательной записи книги для согласованного командного использования.
