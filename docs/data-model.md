# Полка — модель данных

Обновлено: 25 ноября 2026 года. Статус: пользовательский словарь подтверждён; по новому решению основное хранилище — Excel `.xlsx`. Логическая структура и раскладка листов ниже предложены для согласования. Основание: исходный словарь и поздние решения текущего чата, имеющие приоритет.

## Подтверждённые пользовательские поля

Все пользовательские поля необязательны при создании и редактировании любой карточки. Можно сохранить любую часть сведений и дополнить позже. Состав полей перенесён из исходного словаря; обязательность и связанные проверки обновлены по решению пользователя в текущем чате от 24.11.2026. Поздние решения о вариантах, дублях и конфликтах — в BR-02–04 и BR-08.

| Поле | Формат | Обязательно | Подтверждённые правила |
| --- | --- | --- | --- |
| Название | Текст | Нет | Название конкретной страницы. По нему работает поиск. Одинаковые названия у разных страниц допускаются; уникальность по названию не проверяется |
| Тип | Одно значение из списка | Нет | Проект или Продукт, если заполнен |
| Статус | Одно значение из списка | Нет | Шесть значений BR-05, если заполнен. Назначается вручную, разрешён любой переход |
| Тематика | Одна тематическая группа | Нет | Выбирается вручную. Без значения карточка показывается в «Без темы» |
| Ссылки на страницы в Tilda | Ссылки конкретной страницы; при двух страницах одного проекта — варианты с подписями | Нет | Если заполнены, ведут на конкретную страницу конструктора; общий проект или папка не подходят. Проверка дублей по pageid, включая корзину |
| Ссылки в проде | Ссылки страницы; при двух страницах одного проекта — варианты с подписями | Нет | Могут отсутствовать, в том числе вне Tilda. Старый URL сохраняется для снятой с публикации страницы. По нему работает поиск; уникальность не требуется |
| Репозиторий | Ссылка | Нет | Необязателен, в том числе вне Tilda; можно дополнить позже или указать вместе с сайтом |
| Заказчик | Свободный текст | Нет | Организация, подразделение, имя человека или сочетание. Не объединяется с ответственным |
| Ответственный | Один человек, если заполнен | Нет | Для новой карточки — лид направления; старое назначение при импорте сохраняется буквально без подмены текущим лидом. Автоматического сопоставления по имени нет; корпоративная привязка — Q-10 |
| Исполнители | Список сотрудников, может быть пустым | Нет | Могут работать над несколькими страницами. Имена в существующих карточках сохраняются после ухода сотрудника |
| Дата начала работ | Дата; для неточных старых значений — исходный текст | Нет | Неизвестную дату не заполняют; не подставляют дату импорта вместо даты начала работ |
| Ссылки на ТЗ | Список ссылок | Нет | Несколько ссылок, без отдельных подписей. Совпадение ссылок между карточками допускается |
| Лог ТЗ | Текст | Нет | Короткое описание задачи |
| Дата последних изменений страницы | Дата; для неточных старых значений — исходный текст | Нет | Заполняется вручную, независимо от описания. Относится к изменениям страницы, не к карточке. Заполненная точная дата — сегодняшняя или прошедшая; будущие запрещены |
| Описание последних изменений страницы | Текст | Нет | Что меняли: текст, изображения, блоки и т. п. Можно сохранить без даты и дополнить позже. Только последняя запись, без автора и истории |
| Технологии и интеграции | Несколько тегов из справочника | Нет | Сотрудники выбирают готовые теги, новые создаёт только лид |
| Ссылки на макеты Figma | Список ссылок | Нет | Обычно одна, иногда несколько. Без отдельных подписей. Совпадение ссылок между карточками допускается |
| Превью | Загружаемое изображение | Нет | Скриншот актуального первого экрана, загружается и заменяется вручную. Без него — нейтральная заглушка. Форматы PNG, JPG/JPEG и WebP; размер одного файла не более 5 МБ |

Дата окончания работ исключена. Лог ТЗ не является описанием последнего изменения. Дополнительные исходные поля остаются в снимке и бэклоге; их наличие в источнике не создаёт поля интерфейса. Продуктовых лимитов длины текста и числа ссылок пока нет. Технические численные пределы будут предложены при выборе стека (Q-11), сейчас они не утверждены. Точные даты отображаются как `ДД.ММ.ГГГГ`; «сегодня» для проверки даты последних изменений — день по `Europe/Moscow`.

## Подтверждённые системные сведения

| Сведение | Назначение |
| --- | --- |
| Время редактирования карточки | Автоматически при создании и сохранении правок; сортировка, отдельно от ручной даты |
| Нахождение в корзине | Отдельно от статуса; удаление и восстановление |
| Исходный порядок импорта | Фактический порядок листов и строк; взаимный порядок не редактировавшихся импортированных карточек сохраняется |

Точные правила: BR-07, BR-09 и BR-12. Физические поля для этих сведений не утверждены.

## Предлагаемая логическая структура

| Сущность | Связи и назначение | Статус |
| --- | --- | --- |
| Карточка | Устойчивый внутренний ID, пользовательские сведения, тип, статус, необязательная тема | Предложение хранения |
| Вариант | Подпись и адреса двух страниц одного проекта, например RU / EN; без своего статуса и превью | Пользовательское правило утверждено, физическое хранение предложено |
| Ссылка материала | Несколько ТЗ и Figma на карточку; без подписей | Предложение хранения утверждённых списков |
| Человек | Отдельно от корпоративной учётной записи; старые имена и назначения сохраняются буквально | Автоматического сопоставления по имени нет; корпоративная интеграция — Q-10 |
| Тематика | Одна либо отсутствует у карточки | Предложение хранения |
| Тег и назначение | Несколько тегов у карточки, старые связи удалённого тега сохраняются; повторное добавление имени возвращает тот же тег | Правило утверждено, физическое хранение предложено |
| Превью | Один текущий файл на карточку, метаданные и ссылка на хранилище | Предложение хранения, Q-11 |
| Происхождение импорта | Снимок, лист, строка, исходный порядок, связь с итоговой карточкой | Служебное предложение, не новые поля интерфейса |

Отдельное пользовательское поле «Tilda / вне Tilda» не утверждено. Обязательной ветви заполнения по платформе нет; форму следует проработать без требования выбрать платформу ради сохранения. Репозиторий остаётся полем карточки; отдельные репозитории вариантов не вводятся без решения.

## Предлагаемые ограничения хранения

- Разделить точную дату и исходный текст неточной старой даты. Для неточного значения точная дата пуста; интерфейс показывает исходный текст, включая опечатку. Для новых карточек текстовый ввод даты не вводится.
- Системное время хранить отдельно от обеих ручных дат. Выделить признак/ключ исходного порядка и отдельно время последующего сохранения. Не задавать фиктивные даты изменений сайта ради сортировки.
- Сохранить ключ прежнего места карточки при перемещении в корзину: восстановление не повышает карточку в сортировке. Операции со справочниками также не меняют порядок связанных карточек; это может требовать отдельного ключа сортировки от технического времени изменения связей.
- Допускать пустые пользовательские значения в новых и старых карточках при создании и редактировании, включая название, тип, статус, людей и блок изменений. Не создавать фиктивные значения. Проверки заполненного формата действуют независимо от полноты.
- Проверять уникальность заполненного pageid среди всех записей рабочей книги, включая варианты и корзину, в одной последовательной операции сохранения. Исходная ссылка хранится отдельно; дополнительные параметры не создают новую идентичность. Собственная карточка исключается из поиска чужих дублей. При импорте конфликт сначала попадает в отчёт, а не объединяется автоматически. Это проверка приложения, не ограничение SQL-базы.
- Хранить версию карточки для проверки одновременных правок. Версия — механизм сохранения, не история действий пользователя.
- Удаление темы обнуляет связь карточки; удаление тега делает его недоступным для новых назначений, оставляя старые связи. Повторное добавление имени удалённого тега активирует ту же запись с прежними связями, без второго одинакового тега.
- Исторические люди не исчезают из карточек при изменении корпоративного доступа. Имя не используется как уникальный ключ корпоративного аккаунта.
- Начальные тематики заданы предметными листами по BR-10; исходные 7 тегов и 4 дополнительных имени утверждены в BR-11, всего 11 тегов. Проверка исходных назначений выполняется при подготовке импорта.
- Хранить полный исходный снимок вне пользовательской модели MVP; в нём остаются поля бэклога и поясняющий текст ссылок.

Это предложения реализации существующих правил. Имена листов, колонки XLSX, API-контракты, библиотека чтения/записи и технические пределы ещё не согласованы. Планирование и история действий не получают листы в MVP. PostgreSQL и SQL-схема из прежнего предложения заменены решением пользователя о книге Excel.

## Предлагаемая структура Excel

Одна рабочая книга, например `polka.xlsx`, — основное постоянное хранилище. Имена листов предлагаются на английском. Это внутреннее устройство хранения, а не новые поля формы или дополнительные экраны.

| Лист | Что хранит |
| --- | --- |
| Cards | Системный ID карточки, необязательные общие поля, тип, статус, тема, ответственный, даты/текст старых дат, корзина, версия и ключ сортировки |
| Variants | ID варианта и карточки, подпись, Tilda URL, pageid и опубликованный URL для двух страниц одного проекта |
| Links | Списки ссылок карточки на ТЗ/Figma, репозиторий и адреса страницы вне пары вариантов; принадлежность и порядок |
| People | Устойчивые ID и сохранённые исторические имена без автоматической связи с корпоративным аккаунтом |
| CardPeople | Связь карточек и исполнителей |
| Topics | ID, имена и порядок тематик |
| Tags | ID, имена и доступность тегов для нового назначения |
| CardTags | Старые и текущие назначения тегов |
| Previews | Привязка текущего файла превью, метаданные и путь в закрытом хранилище |
| ImportMap | Происхождение из снимка, листа и строки; соответствие карточке и исходный порядок |
| Meta | Версия структуры книги и техническая ревизия |

Окончательное место опубликованного URL одиночной страницы и репозитория в листах уточняется при проектировании, но в пользовательской карточке поля остаются прежними. Дублирование адресов между листами не должно создавать два источника истины.

Идентификаторы — текстовые стабильные значения; номера строк не являются ключами. Все 18 пользовательских полей могут отсутствовать, системные ID/версии формирует приложение. Точные даты предлагается сохранять без времени как ISO-текст `YYYY-MM-DD` и отображать ДД.ММ.ГГГГ; исходный текст неточных дат — отдельно. Исходный пользовательский текст записывается как текст, а не формула. При чтении проверяются типы, ссылки между листами, уникальность ID и pageid; отсутствие пользовательских значений не является ошибкой.

Пределы ячейки XLSX, длинные тексты и гиперссылки должны быть проверены до импорта; обрезать значения ради успешной записи нельзя. Обработка превышений и точные технические пределы остаются Q-11. Изменение схемы — проверяемое преобразование копии книги с резервированием, а не SQL-миграция. Сохранение, блокировки и обнаружение внешних изменений описаны в [architecture.md](architecture.md).

## Импорт

Карта колонок, названия листов, семь неполных ссылок Tilda, пять строк вариантов и остальные исключения находятся в [import-plan.md](../polka-transfer/import-plan.md). Ссылки и видимый текст ячеек учитываются отдельно; опубликованный URL не превращается в ссылку конструктора. Для «расположения на сервере» утверждено: опубликованный URL — в ссылки сайта, внутренний путь/пояснение — только в исходный снимок, без нового поля. Спорные строки вариантов разбираются перед импортом без автоматического разделения и потери ссылок.

Снимок и отчёт отсутствуют в текущем проекте; до их восстановления импорт заблокирован. Числа из исходного отчёта не заменяют повторную проверку восстановленного снимка. Источник → карточка должен сверяться без использования названия как уникального ключа; повторяемый служебный импорт — предложение реализации, не экран повторного импорта.
