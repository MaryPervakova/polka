# Полка — продуктовое видение

Дата: 24 ноября 2026 года. Статус: перенос подтверждённых сведений. Основание: [Product Brief](../polka-transfer/product-brief.md), разделы 1–3, 7–9.

## Цель и проблема

«Полка» — внутренний сервис команды дизайна для хранения сведений о страницах и ссылок на материалы. Основная работа ведётся со страницами Tilda; две известные страницы вне Tilda также включены в MVP.

Сейчас справочная информация и планирование ведутся в двух файлах. Сотрудники ищут ссылки, переключаются между файлами и повторно вносят сведения. MVP заменяет первый файл для справочной работы. Главная польза — быстро найти нужную страницу для изменений или просмотра информации и быстро добавить новую.

## Пользователи и ответственность

Каталог доступен всей команде дизайна. Сотрудники направления Тильда ведут карточки; коллеги других направлений ищут и просматривают сведения, открывают материалы. Лид отвечает за актуальность данных и управляет справочниками. Полная матрица прав: [BR-01](business-rules.md#br-01-доступ).

До подключения корпоративного SSO сервис используется только инициатором в процессе разработки. Командный запуск — отдельный этап. Протокол корпоративного входа ещё не определён.

## Единица работы

Карточка соответствует странице проекта. Варианты используются только когда у одного проекта две страницы, например RU / EN. Все поля можно заполнять постепенно: обязательных полей нет. Тип «Проект» используется для промостраницы; «Продукт» — для страницы масштабного продукта. Различие связано с назначением и масштабом, а не только количеством страниц. Общая карточка продукта и вложенность отсутствуют в MVP.

## Критерий успеха

Сотрудники всей команды дизайна самостоятельно находят материалы. Сотрудники Тильды добавляют и обновляют сведения, первый файл больше не нужен для справочной работы. До SSO возможна проверка инициатором, но она не подтверждает готовность командного запуска.

Численные цели скорости поиска и заполнения не установлены. Их отсутствие не разрешает придумывать показатели приёмки.

## Граница

Состав MVP и отложенные функции определены в [требованиях](product-requirements.md). Будущее собственное планирование внутри «Полки» сохраняется как направление развития; интеграция с Jira возможна позднее и не является условием MVP.
