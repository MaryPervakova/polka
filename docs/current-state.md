## Последние продуктовые решения

В текущем чате 24.11.2026 пользователь уточнил варианты и отменил обязательные поля, а пункты 2 (дубли) и 4 (конфликт) утвердил:

- Варианты — только для двух страниц одного проекта, например русской и английской. Старые строки с большим числом ссылок требуют сверки импорта Q-12, без автоматического разделения.
- Все пользовательские поля необязательны при создании и изменении всех карточек. Можно сохранять любую часть сведений и дополнять позже; дата и описание также не требуют совместного заполнения. Прежний минимум и запрет очистки обязательных полей больше не действуют. Форматы заполненных значений и запрет дублей сохраняются.
- Tilda сравнивается по pageid при создании и изменении, с учётом корзины и исключением собственной карточки; исходная ссылка сохраняется, нераспознанная получает пояснение без автоматического исправления.
- При конфликте сохранение отклоняется, введённое остаётся в форме; актуальная версия открывается отдельно через соответствующее действие, нужные правки переносятся вручную. Автоматического объединения и принудительной перезаписи нет.

Рабочие документы, модель, сценарии и чек-лист обновлены. Эти решения имеют приоритет над четырьмя неизменными исходниками; совпадение обязательности полей с исходным словарём больше не является критерием корректности.

Следующим ответом пользователь утвердил поиск, возврат удалённого тега, ограничение просмотра корзины и отсутствие автоматического приоритета статусов, с поправкой о множественном выборе в фильтрах:

- По части названия — без учёта регистра; по опубликованному URL — полный адрес или часть без `https://`. Показываются все совпадения; пустой результат — «Ничего не найдено» с возможностью сбросить фильтры.
- В каждом фильтре несколько значений: «ИЛИ» внутри фильтра, «И» между фильтрами и поисковым запросом. Пустой фильтр не ограничивает выдачу.
- Повторное добавление имени удалённого тега лидом возвращает тот же тег в доступные с сохранением старых назначений, без второго одинакового тега.
- Корзина доступна лиду и сотрудникам Тильды; другим направлениям скрыта и недоступна.
- Статус выбирается вручную; автоматического приоритета и исправления по другим признакам нет.

Затем пользователь утвердил Q-05 и Q-06:

- Тематики берутся по предметным листам реестра с сохранением названий; архивный таб — «Архивные в паблике». Начальный порядок — фактический порядок листов и строк источника.
- Восстановление возвращает карточку на прежнее место в сортировке. Изменение справочников тематик и тегов не поднимает связанные карточки.
- Старые имена и назначения сохраняются буквально без автоматического связывания с корпоративными аккаунтами. Исторический ответственный не подменяется текущим лидом; корпоративная привязка остаётся Q-10.
- Дополнительные Three.js, `<model-viewer>`, lidrekon, GoogleSheet утверждены; вместе с исходными семью это 11 начальных тегов.

Затем пользователь утвердил правила Q-12 и продуктовую часть Q-14:

- Точные даты — ДД.ММ.ГГГГ, проверка «сегодня» — по Москве; неточные старые даты остаются исходным текстом.
- Продуктовых лимитов длины текста и числа ссылок пока нет. Численные технические пределы предлагаются при выборе стека и остаются открытой частью Q-11.
- Публикационный URL из «расположения на сервере» переносится в ссылки сайта; внутренние пути/пояснения остаются только в снимке без нового поля карточки.
- Спорные строки с несколькими страницами разбираются до импорта без автоматического разделения и потери ссылок. До восстановления снимка и отчёта импорт заблокирован; конкретные строки ещё не проверены.

Последнее уточнение по техническому этапу:

- Сначала приложение будет локальным на компьютере пользователя; затем предполагается сервер компании. Параметры и выделение сервера пока не подтверждены.
- Корпоративный SSO ещё в разработке. Q-10 остаётся внешней зависимостью командного запуска, не блокирующей подготовку локальной версии.

В README и инструкции набор обозначен для прототипов/локальных демо, не production; до постоянного серверного запуска нужно уточнить поддерживаемый путь у команды набора. Установка и фактическая проверка не выполнялись, версии проекта не утверждены.

## Действующий выбор стека от 25.11.2026

Утверждены React + TypeScript + Vite, базовый CSS и локальные стили через sx, React-компоненты `.tsx`. Основное постоянное хранилище — одна книга Excel `.xlsx`, не только экспорт и не исходный Google-реестр. IC Kit сохраняется; поддержка sx конкретными компонентами не проверена.

Предложены локальный сервер (кандидат Node 26 / Fastify 5), ExcelJS, последовательная запись книги через временный файл с проверкой и резервированием, версии карточек и обнаружение внешних изменений. В data-model.md предложены листы со стабильными ID. Превью — отдельными файлами с метаданными в книге. Серверная часть, библиотека, схема и способы сохранения пока не утверждены и не реализованы; Excel-книга не создавалась агентом.

Предложение PostgreSQL, драйвера pg и SQL-миграций заменено выбором Excel. Прежний предел JSON 16 МиБ не утверждён. Для sx предложен типизированный адаптер над обычными CSS-свойствами без добавления другой дизайн-системы. Требуются проверки границ XLSX, чтобы сохранять данные без обрезания и выполнять прежние правила дублей, конфликтов, корзины и сортировки.

Read-only проверка: macOS 15.7.4 arm64, Node v26.13.0 и npm 12.2.2 доступны; psql и docker в PATH не обнаружены. Проверка установленного окружения не является установкой зависимостей проекта или тестом приложения.
