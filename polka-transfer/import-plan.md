Папка Tilda не является конкретной страницей. В двух строках вместо конструктора стоит опубликованный URL. Не придумывать недостающие pageid и не открывать папки для изменения данных. Дополнение ссылок — отдельная подготовка; старые неполные записи разрешены.

### Статусы и архивный лист

На листе «Архивные (в паблике)» 22 строки: 18 со статусом «Активен», 2 — «Требует проверки», 2 — «Архив». В источнике в выпадающем списке нет нового статуса «Архив в паблике». Поэтому название листа нельзя автоматически трактовать как достоверное состояние публикации каждой страницы. Решение 83: преобразование отклонено; все исходные статусы сохраняются, записи размещаются в табе «Архивные в паблике».

### Даты и описание изменений

Встречаются «2021 год», «октябрь 2025», «начало 2026 года», «Регулярно», диапазон «13-20 ноября 2026», а также опечатка «октиябрь 2026». Не превращать год или месяц в вымышленное точное число. Правило будущей даты относится к точной дате последних изменений, а неполные старые записи сохраняются по исключению импорта.

В листах нет отдельной колонки «Что меняли» для последних изменений; есть лог ТЗ. В восьми строках Tilda лог ТЗ заполнен, но это не разрешение считать его описанием последнего изменения.

### Люди и теги

В заполненных полях ответственного и исполнителей листов Tilda встречаются: Рита, Арсений, Вероника, Маша, Вадим, Катя, Глеб. Все имена должны сохраниться; автоматическая привязка по одному имени к корпоративному аккаунту без проверки недопустима.

Кроме семи утверждённых тегов в строках Tilda встречаются Three.js, <model-viewer>, lidrekon и GoogleSheet (всего три строки с такими дополнительными значениями). Их включение в справочник решает лид. Не заменять неизвестные теги похожими и не терять исходные значения.

### Ссылки и поясняющий текст

У некоторых ячеек адрес находится в гиперссылке, а на экране видна подпись, например в «Перекрытия + кампании» E7 и E8. В других ячейках есть URL и пояснения («Редизайн», «Последняя актуальная задача»). В части ссылок видимый текст и фактический адрес различаются лишь кодировкой кириллицы — это не обязательно ошибка.

Для подготовки импорта сохраняются и текст ячейки, и hyperlink, и ссылки отдельных текстовых фрагментов. Поля «Еще не в паблике» или «снято с публикации» не становятся URL. Сведения из них сохраняются для проверки и не меняют статус автоматически.

### «Не на Tilda»

Две страницы: «Гараж ЦОДД» и «Электросудно». В источнике у них GitHub и расположение на сервере, а не ссылка Tilda. Ответ 82 подтверждает включение обеих страниц в MVP. Сохранить исходные GitHub и расположение без подмены ссылкой Tilda; для новых карточек вне Tilda по ответу 88 обязательна хотя бы одна ссылка: опубликованный сайт или репозиторий.

## 6. Предлагаемый процесс переноса

Это проект реализации, не уже выполненный импорт.

1. Зафиксировать снимок источника с названиями листов, координатами строк, текстом и URL.
2. Отделить индекс «Реестр», «Шаблон», пустые строки и служебные разделы от карточек.
3. Составить кандидаты карточек по предметным листам, сохраняя происхождение каждой строки.
4. Применить решения 82–84: включить «Не на Tilda», сохранить архивный таб и статусы, оставить варианты в одной карточке. Применить решение 85: отображать неточные даты исходным текстом. Дополнительные поля отложить в бэклог по ответу 86; дополнительные теги согласовать с лидом.
5. Подготовить сопоставление имён и справочников; назначение ролей не выводить из старого поля «Ответственный».
6. Выполнить предварительный прогон без записи в сервис: количество строк, кандидатов, исключений и дублей.
7. Проверить небольшой набор разных случаев: простая страница, продукт из одной страницы, архив, несколько ссылок, неполная запись.
8. Выполнить разовый импорт согласованного набора. Не требовать заполнить все пропуски старых карточек и не выводить отметку «Не хватает данных».
9. Пользователь проверяет результат. Сверить количество исходных строк, число итоговых карточек и сохранённых вариантов и все исключённые строки.
10. Зафиксировать таблицу соответствия «источник → карточка сервиса». Предложение для реализации: повторный запуск не создаёт дубли; не использовать имя страницы как ключ.

Постоянная двусторонняя синхронизация с таблицей и отдельный экран повторного импорта не входят в согласованный MVP.

## 7. Как учесть файл 2 в дальнейшем

Возможную интеграцию с Jira рассмотрим в дальнейшем; сейчас она не является условием разработки планирования. Использование Jira для ведения задач разработки самого сервиса не означает интеграцию продукта с Jira.

Проверен образец листа «ДК-2026 (копия)», sheetId 526977552. Другие листы «Родмап» и «Лист1» скрыты; они не выбраны автоматически как актуальный источник.

Названия планируемых работ отличаются от названий карточек реестра. Связь нельзя строить только по совпадению текста.

Предложение для архитектуры: у каждой карточки должен быть устойчивый внутренний идентификатор. Будущий план и задачи связываются с ним; переименование карточки и смена URL не разрывают план. Одна карточка — один роадмап по ранее принятому решению. Это не требует включать задачи в MVP.

Статусы «В работе» и «Ждем ОС» из планирования нельзя автоматически заменять на «Активен» или «Черновик» справочной карточки. Это отдельная логика, которую нужно согласовать на этапе интеграции.

Для будущего импорта роадмапов потребуется отдельно проверить все блоки, объединённые ячейки, точный год, значение цветов, интервалы и права лида. Текущая проверка не устанавливает готовность полного импорта файла 2.

## Решения по ответам 82–84

- **82. Не на Tilda.** Две страницы листа «Не на Tilda» включаются в MVP. Для них ссылка Tilda не требуется. Для новой карточки страницы вне Tilda требуется хотя бы одна ссылка: на опубликованный сайт или репозиторий. Можно заполнить обе; ссылка Tilda не требуется (ответ 88). Остальные обязательные поля сохраняются; для старого импорта действует исключение неполных записей.
- **83. Архивный таб.** Страницы исходного листа «Архивные (в паблике)» остаются в отдельном табе «Архивные в паблике». Статус каждой карточки сохраняется из файла: 18 «Активен», 2 «Требует проверки», 2 «Архив». Таб и статус независимы; перенос в этот таб не меняет статус. Ответ также закрывает вопрос 87.
- **84. Варианты страницы.** Строки с несколькими вариантами страницы не разделяются автоматически на карточки. В одной карточке можно разместить несколько ссылок с подписями, объясняющими различия, например RU / EN. Это меняет прежнее правило строго одной страницы и одной ссылки Tilda на карточку, но не вводит вложенные карточки продукта. Подписи относятся к ссылкам на варианты; правило ссылок ТЗ и Figma без подписей сохраняется.

Проверка дублей Tilda применяется к каждой ссылке на конкретную страницу среди вариантов, включая карточки в корзине. Совпадающие опубликованные URL по-прежнему не запрещены. Поиск по опубликованному адресу должен находить карточку по любому её варианту. Варианты используют общие сведения карточки; отдельные статусы, исполнители и превью каждого варианта не утверждены.

## Решения по ответам 85–86

- **85. Неточные старые даты.** Сохранять и отображать исходный текст, например «октябрь 2025» или «2021 год». Не придумывать день, не заменять значение датой импорта. Если точной даты нет, поле точной даты остаётся пустым, а исходное значение доступно в карточке как текст. Это исключение для переноса старых данных; оно не отменяет проверку точных дат последних изменений и не вводит свободный формат даты при создании новых карточек. Сортировка каталога по-прежнему использует системное время карточки.
- **86. Бэклог: дополнительные поля реестра.** Ссылка на Яндекс Метрику, посещаемость, MAU, описание и назначение, блоки и механики анимаций, обратная связь заказчика, бэклог и идеи развития, комментарий — отложены за пределы MVP. Добавление этих полей и их отображение в карточке относятся к бэклогу развития «Полки». Исходные значения уже сохранены в source-registry-snapshot.json; не удалять их. Автоматическая интеграция с Метрикой и сроки реализации не утверждены.

## Решения по ответам 61, 88–89

- **61. Доступ других направлений.** Коллегам из других направлений доступны только просмотр, поиск и переход по ссылкам на страницы и материалы. Создание, редактирование, удаление и восстановление карточек, а также изменение справочников им недоступны (ответ 61).
- **88. Страницы вне Tilda.** Для новой карточки страницы вне Tilda требуется хотя бы одна ссылка: на опубликованный сайт или репозиторий. Можно заполнить обе; ссылка Tilda не требуется (ответ 88). Остальные обязательные поля сохраняются; для старого импорта действует исключение неполных записей.
- **89. Незавершённые правки.** Если правки страницы со статусом «На поддержке» ещё не закончены, сотрудник вручную ставит «Черновик» (ответ 89). Это правило не запускает автоматических переходов. После завершения правок сотрудник вручную возвращает «На поддержке» (ответ 90).

## Решения по ответам 90–91

- **90. Завершение правок.** Для страницы, которая была «На поддержке», после завершения правок вручную возвращается «На поддержке». Автоматический переход не предусмотрен.
- **91. Начальный порядок.** При первоначальном переносе сохраняется порядок исходного реестра (ответ 91), в том числе порядок строк внутри соответствующих табов. После сохранения правок в «Полке» карточка участвует в обычной сортировке по системному времени редактирования, от новых изменений к старым; взаимный исходный порядок ещё не редактировавшихся импортированных карточек сохраняется. Просмотр и переход по ссылкам порядок не меняют. Технический способ хранения начального порядка не задаётся этим решением.

## Решения по результатам встречи: ответы 92–97

- **92. Метрика.** Даже простая ссылка на Яндекс Метрику остаётся в бэклоге; текущие поля MVP не расширяются.
- **93, 97. Доступ до SSO.** Этап разработки: до подключения SSO сервисом пользуется только инициатор проекта (пользователь). Временный вход для команды не требуется; командный доступ на этом этапе не открывается (ответы 93, 97). Корпоративный SSO подключается по готовности. Согласованные роли лида, сотрудников Тильды и других направлений сохраняются для командного запуска; собственная регистрация и локальные приглашения не вводятся.
- **94. UI-kit.** При создании интерфейса используется внутренний [IC Kit](https://icdesign-bt.github.io/ic-kit/?path=/story/introduction--docs) (ответ 94). Ссылка предоставлена пользователем как источник UI-kit; конкретные компоненты, версия пакета и способ подключения ещё не проверены и не утверждены.
- **95, 96. Дальнейшее развитие.** Решения встречи (ответы 92–97) не меняют состав первичного импорта: ссылка на Метрику остаётся в бэклоге, данные сохраняются в снимке; история действий и планирование не создаются автоматически из полей реестра. Первоначальная подготовка сервиса до SSO выполняется для использования только инициатором.
