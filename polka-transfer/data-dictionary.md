# Полка — словарь данных MVP

Версия: 0.10
Дата: 24 ноября 2026 года
Статус: рабочий документ; подтверждённые правила и открытые вопросы разделены.
Основание: product-brief.md v0.30, scenarios-and-rules.md v0.27, ответы 1–97.

## 1. Назначение

Документ описывает, какие сведения хранит карточка страницы, как они заполняются и что проверяет сервис. Это основа для формы, хранения данных и переноса из таблицы; конкретная технология хранения пока не выбрана.

Карточка соответствует странице или группе её вариантов со ссылками и подписями различий. Типы «Проект» и «Продукт» используют одинаковые поля. Общей карточки многостраничного продукта в MVP нет.

## 2. Поля, которые заполняет сотрудник

«Обязательно» ниже означает создание новой карточки. Для перенесённых старых записей действует исключение из раздела 6.

| Поле | Формат | Обязательно | Подтверждённые правила |
| --- | --- | --- | --- |
| Название | Текст | Да | Название конкретной страницы. По нему работает поиск. Одинаковые названия у разных страниц допускаются; уникальность по названию не проверяется |
| Тип | Одно значение из списка | Да | Проект или Продукт |
| Статус | Одно значение из списка | Да | Шесть значений из раздела 3. Назначается вручную, разрешён любой переход |
| Тематика | Одна тематическая группа | Нет | Выбирается вручную. Без значения карточка показывается в «Без темы» |
| Ссылки на страницы в Tilda | Список ссылок на варианты с подписями различий | Для страниц Tilda | Ссылка на конструктор. По ней запрещены дубли, включая корзину. Требуется конкретная страница в конструкторе; ссылка только на общий проект Tilda не подходит |
| Ссылки в проде | Список ссылок на варианты с подписями различий | Для вне Tilda — сайт или репозиторий | Может отсутствовать. Старый URL сохраняется для снятой с публикации страницы. По нему работает поиск; уникальность не требуется |
| Репозиторий | Ссылка | Для вне Tilda — сайт или репозиторий | Как минимум одно из двух полей требуется для новой карточки вне Tilda; обе ссылки допустимы |
| Заказчик | Свободный текст | Нет | Организация, подразделение, имя человека или сочетание. Не объединяется с ответственным |
| Ответственный | Один человек | Да | Лид направления. Способ выбора и сопоставление с корпоративными учётными записями уточняются |
| Исполнители | Один или несколько сотрудников | Да, хотя бы один | Могут работать над несколькими страницами. Имена в существующих карточках сохраняются после ухода сотрудника |
| Дата начала работ | Дата; для неточных старых значений — исходный текст | Нет | Неизвестную дату не заполняют; не подставляют дату импорта вместо даты начала работ |
| Ссылки на ТЗ | Список ссылок | Нет | Несколько ссылок, без отдельных подписей. Совпадение ссылок между карточками допускается |
| Лог ТЗ | Текст | Нет | Короткое описание задачи |
| Дата последних изменений страницы | Дата; для неточных старых значений — исходный текст | Нет | Заполняется вручную. Относится к изменениям страницы, не к правкам её карточки. Допустимы сегодняшняя и прошедшие даты, будущие запрещены. Если блок заполняется, нужны и дата, и описание; весь блок можно оставить пустым |
| Описание последних изменений страницы | Текст | Нет | Что меняли: текст, изображения, блоки и т. п. Хранится только последняя запись, без автора и истории предыдущих записей. При заполнении блока требуется также дата |
| Технологии и интеграции | Несколько тегов из справочника | Нет | Сотрудники выбирают готовые теги, новые создаёт только лид |
| Ссылки на макеты Figma | Список ссылок | Нет | Обычно одна, иногда несколько. Без отдельных подписей. Совпадение ссылок между карточками допускается |
| Превью | Загружаемое изображение | Нет | Скриншот актуального первого экрана, загружается и заменяется вручную. Без него — нейтральная заглушка. Форматы PNG, JPG/JPEG и WebP; размер одного файла не более 5 МБ |

Дата окончания работ исключена. Посещаемость и интеграция Яндекс Метрики не входят в утверждённые поля MVP.

Численные ограничения длины текста и количества ссылок пока не согласованы. Их нельзя выдавать за подтверждённые решения пользователя.

## 3. Список статусов

| Значение | Значение для команды |
| --- | --- |
| Черновик | Страница или задача в работе, включая правки к уже опубликованной странице |
| Активен | Страница в проде; команда выполнила работу от макета до публикации |
| На поддержке | Макет выполнен не направлением, но команда реализовала страницу в Tilda |
| Требует проверки | Со страницей что-то не так, требуется проверка |
| Архив | Страница снята с публикации |
| Архив в паблике | Старая опубликованная страница, давно не корректируется |

Статусы не запускают публикацию или снятие с публикации в Tilda. Если правки страницы со статусом «На поддержке» ещё не закончены, сотрудник вручную ставит «Черновик» (ответ 89). Это правило не запускает автоматических переходов. После завершения правок сотрудник вручную возвращает «На поддержке» (ответ 90). Приоритет в остальных пересечениях признаков ещё не определён.

## 4. Справочники и права

### Тематики

Основа списка — тематические листы исходного реестра. Названия и структура листов сверены 24 ноября 2026 года и перечислены в import-plan.md. «Архивные в паблике» сохраняется отдельным табом без изменения исходных статусов. Две страницы «Не на Tilda» включаются в MVP. У страницы одна тематика или ни одной. «Без темы» означает отсутствие значения, а не обязательно отдельную запись справочника.

Создание и переименование тематик доступны только лиду. Удалять тематику может только лид. При удалении её страницы переходят в «Без темы»; сами карточки, ссылки и материалы сохраняются.

### Технологии и интеграции

Исходные значения со скриншота:

- Tilda zeroblock
- Vibe-coding
- Стандартный блоки
- HTML
- CSS
- JavaScript
- 2ГИС

Название «Стандартный блоки» сохранено как в источнике. Теги может добавлять и удалять только лид. Переименование тегов в MVP не предусмотрено. Удаление выводит тег из доступных для нового выбора, но сохраняет его в карточках, где он уже был назначен. Обычное редактирование такой карточки не должно удалять старый тег. Запрет нового назначения действует и при создании карточки, и при добавлении тега в существующую.

### Люди и доступ

Этап разработки: до подключения SSO сервисом пользуется только инициатор проекта (пользователь). Временный вход для команды не требуется; командный доступ на этом этапе не открывается (ответы 93, 97). Корпоративный SSO подключается по готовности. Согласованные роли лида, сотрудников Тильды и других направлений сохраняются для командного запуска; собственная регистрация и локальные приглашения не вводятся. Вся команда дизайна может просматривать каталог. Коллегам из других направлений доступны только просмотр, поиск и переход по ссылкам на страницы и материалы. Создание, редактирование, удаление и восстановление карточек, а также изменение справочников им недоступны (ответ 61).

Заказчик хранится отдельно от сотрудников-исполнителей и ответственного. Конкретные системные идентификаторы людей и сопоставление старых имён определяются при подготовке интеграции и импорта.

## 5. Системные сведения и порядок каталога

| Сведение | Источник | Назначение |
| --- | --- | --- |
| Время редактирования карточки | Автоматически при создании и сохранении правок | Сортировка от новых изменений к старым. Просмотр и переход по ссылкам время не обновляют |
| Нахождение карточки в корзине | Действия удаления и восстановления | Отдельно от статуса страницы. Не удаляет внешние материалы |

При первоначальном переносе сохраняется порядок исходного реестра (ответ 91), в том числе порядок строк внутри соответствующих табов. После сохранения правок в «Полке» карточка участвует в обычной сортировке по системному времени редактирования, от новых изменений к старым; взаимный исходный порядок ещё не редактировавшихся импортированных карточек сохраняется. Просмотр и переход по ссылкам порядок не меняют. Технический способ хранения начального порядка не задаётся этим решением. Приведены логические сведения; технические имена полей и структура базы данных здесь не утверждаются.

На карточке каталога показываются только превью, название и статус. Поиск работает по названию и опубликованному адресу сразу по всем тематикам. Фильтры: статус, тип, исполнитель.

## 6. Проверки и перенос

1. При создании новой карточки необходимы название, тип, статус, ответственный, хотя бы один исполнитель и, для страниц Tilda, минимум одна ссылка на конкретную страницу в конструкторе.
2. Старые неполные записи переносятся с возможностью дополнить позже, без отметки о неполноте и без изменения статуса по этой причине.
3. Ссылка на страницу в конструкторе Tilda — единственное согласованное основание запрета дублей. Правила сравнения разных вариантов ссылки ещё не определены.
4. Если совпадение найдено в каталоге, предлагается открыть существующую карточку; новая не создаётся.
5. Если совпадение найдено в корзине, предлагается восстановление с учётом действующих прав.
6. При первоначальном импорте дубли из источника выводятся отдельным списком для проверки пользователем, автоматически не объединяются.
7. Для опубликованных адресов, ТЗ и Figma совпадения между карточками не блокируются.
8. Сервис предупреждает о конфликте одновременных правок; детали разрешения конфликта ещё согласуются.
9. Первоначальный перенос автоматический, результат сначала проверяет пользователь. Постоянная синхронизация с таблицей не утверждена.

Проверка 24 ноября 2026 года: 212 именованных строк на 27 листах Tilda и 2 строки на листе «Не на Tilda». Это не число итоговых карточек: 5 строк содержат несколько pageid, 7 не содержат ссылки на конкретную страницу Tilda. Дополнительные исходные поля и гиперссылки сохранены в снимке. Ни импорт, ни изменение источника не выполнялись.

## Решения по ответам 82–84

- **82. Не на Tilda.** Две страницы листа «Не на Tilda» включаются в MVP. Для них ссылка Tilda не требуется. Для новой карточки страницы вне Tilda требуется хотя бы одна ссылка: на опубликованный сайт или репозиторий. Можно заполнить обе; ссылка Tilda не требуется (ответ 88). Остальные обязательные поля сохраняются; для старого импорта действует исключение неполных записей.
- **83. Архивный таб.** Страницы исходного листа «Архивные (в паблике)» остаются в отдельном табе «Архивные в паблике». Статус каждой карточки сохраняется из файла: 18 «Активен», 2 «Требует проверки», 2 «Архив». Таб и статус независимы; перенос в этот таб не меняет статус. Ответ также закрывает вопрос 87.
- **84. Варианты страницы.** Строки с несколькими вариантами страницы не разделяются автоматически на карточки. В одной карточке можно разместить несколько ссылок с подписями, объясняющими различия, например RU / EN. Это меняет прежнее правило строго одной страницы и одной ссылки Tilda на карточку, но не вводит вложенные карточки продукта. Подписи относятся к ссылкам на варианты; правило ссылок ТЗ и Figma без подписей сохраняется.

Проверка дублей Tilda применяется к каждой ссылке на конкретную страницу среди вариантов, включая карточки в корзине. Совпадающие опубликованные URL по-прежнему не запрещены. Поиск по опубликованному адресу должен находить карточку по любому её варианту. Варианты используют общие сведения карточки; отдельные статусы, исполнители и превью каждого варианта не утверждены.

## Решения по ответам 85–86

- **85. Неточные старые даты.** Сохранять и отображать исходный текст, например «октябрь 2025» или «2021 год». Не придумывать день, не заменять значение датой импорта. Если точной даты нет, поле точной даты остаётся пустым, а исходное значение доступно в карточке как текст. Это исключение для переноса старых данных; оно не отменяет проверку точных дат последних изменений и не вводит свободный формат даты при создании новых карточек. Сортировка каталога по-прежнему использует системное время карточки.
- **86. Бэклог: дополнительные поля реестра.** Ссылка на Яндекс Метрику, посещаемость, MAU, описание и назначение, блоки и механики анимаций, обратная связь заказчика, бэклог и идеи развития, комментарий — отложены за пределы MVP. Добавление этих полей и их отображение в карточке относятся к бэклогу развития «Полки». Исходные значения уже сохранены в source-registry-snapshot.json; не удалять их. Автоматическая интеграция с Метрикой и сроки реализации не утверждены.

## Решения по ответам 61, 88–89

- **61. Доступ других направлений.** Коллегам из других направлений доступны только просмотр, поиск и переход по ссылкам на страницы и материалы. Создание, редактирование, удаление и восстановление карточек, а также изменение справочников им недоступны (ответ 61).
- **88. Страницы вне Tilda.** Для новой карточки страницы вне Tilda требуется хотя бы одна ссылка: на опубликованный сайт или репозиторий. Можно заполнить обе; ссылка Tilda не требуется (ответ 88). Остальные обязательные поля сохраняются; для старого импорта действует исключение неполных записей.
- **89. Незавершённые правки.** Если правки страницы со статусом «На поддержке» ещё не закончены, сотрудник вручную ставит «Черновик» (ответ 89). Это правило не запускает автоматических переходов. После завершения правок сотрудник вручную возвращает «На поддержке» (ответ 90).

## Решения по ответам 90–91

- **90. Завершение правок.** Для страницы, которая была «На поддержке», после завершения правок вручную возвращается «На поддержке». Автоматический переход не предусмотрен.
- **91. Начальный порядок.** При первоначальном переносе сохраняется порядок исходного реестра (ответ 91), в том числе порядок строк внутри соответствующих табов. После сохранения правок в «Полке» карточка участвует в обычной сортировке по системному времени редактирования, от новых изменений к старым; взаимный исходный порядок ещё не редактировавшихся импортированных карточек сохраняется. Просмотр и переход по ссылкам порядок не меняют. Технический способ хранения начального порядка не задаётся этим решением.

## Решения по результатам встречи: ответы 92–97

- **92. Метрика.** Даже простая ссылка на Яндекс Метрику остаётся в бэклоге; текущие поля MVP не расширяются.
- **93, 97. Доступ до SSO.** Этап разработки: до подключения SSO сервисом пользуется только инициатор проекта (пользователь). Временный вход для команды не требуется; командный доступ на этом этапе не открывается (ответы 93, 97). Корпоративный SSO подключается по готовности. Согласованные роли лида, сотрудников Тильды и других направлений сохраняются для командного запуска; собственная регистрация и локальные приглашения не вводятся.
- **94. UI-kit.** При создании интерфейса используется внутренний [IC Kit](https://icdesign-bt.github.io/ic-kit/?path=/story/introduction--docs) (ответ 94). Ссылка предоставлена пользователем как источник UI-kit; конкретные компоненты, версия пакета и способ подключения ещё не проверены и не утверждены.
- **95, 96. Дальнейшее развитие.** Ссылка на Метрику остаётся вне полей MVP по ответу 92. Полноценная история действий над сайтом включена в бэклог: дата, сотрудник, описание действия и связанные материалы (ответ 95). Она предназначена для восстановления контекста работ и поиска причин ошибок. Способ формирования и редактирования записей уточняется при проработке функции. В MVP остаётся только последняя запись «дата + описание», без автора и истории; технический журнал изменений карточки — отдельная, пока не утверждённая функция. Поля будущей истории не становятся обязательными полями текущей карточки.
